# 三进制与 Setun 相关论文资料综合分析报告

> 分析对象：`docs/相关论文资料/` 下的全部 6 个顶层资料文件，以及两个压缩包中的论文、书刊、程序手册、电路工程文件和辅助材料。
> 分析日期：2026-07-27
> 面向任务：先实现 3-trit 基础模块，再逐步形成一套可以运行程序的简化三进制体系结构。

> 说明：本仓库收录分析报告和资料索引，不重新分发第三方论文 PDF 与压缩归档。原始材料的文件名和来源信息保留在报告与索引中，便于读者自行查找和核验。

## 1. 结论先行

这批资料很有价值，但它不是一套连续、完整、可以直接照抄的 CPU 设计规范，而是四条不同证据链的混合：

1. **Setun/Setun-70 历史与体系结构资料**：解释平衡三进制、6-trit tryte、栈式执行、分页存储和 POLIZ/DSSP，是研究架构思想的主线。
2. **Cal Poly 三进制计算机项目资料**：给出 3-trit CPU、电路板和 LTspice 仿真的完整教学项目，是当前“先把 3-trit 模块跑通”最直接的工程参考。
3. **现代三值加法器与乘法器论文**：给出平衡/非平衡三值加法器、循环门和 Wallace 树，但多数性能来自器件级仿真，不能直接外推成完整 CPU 的性能。
4. **FeRAM 三值权重论文**：研究神经网络模拟存内计算，不是通用三进制 CPU，只能借鉴三值编码和非理想性测试。

对当前项目最重要的判断是：

- **不要一开始复刻完整 Setun-70。** 历史机器以 6-trit tryte、18-trit操作数、双栈和分页存储为核心，与“先实现 3-trit 寄存器和简单 ALU”的目标跨度过大。
- **第一版应是受 Setun-70 启发的简化机，不应宣称是精确复刻。**
- **算术编码优先固定为平衡三进制 `T/0/1 = -1/0/+1`。**
- **先完成寄存器、加减、取负、比较和最小控制流，乘法器后置。**
- **当前 Python 模拟器适合教学演示，但不是历史 Setun-70 的黄金参考模型。**

## 3. 三篇独立论文/报告

### 3.1 Ternary Computing Testbed 项目报告

文件：`CPE Report - Ternary Computing Testbed - RC6a.pdf`

#### 资料定位

这是 2008 年 Cal Poly 的本科计算机工程项目报告，不是 Setun 复刻。它的价值在于把三值器件、寄存器、ROM、程序计数器、指令译码和应用程序放进了同一个工程闭环。

报告中实际存在三个层次：

- **TCA0**：极简硬件验证机，只实现装载等最基本行为。
- **TCA2**：完整 3-trit 教学架构，在晶体管级 LTspice 和指令级模拟器中运行猜数程序。
- **TCA3**：软件层面的扩展构想，没有与 TCA2 同等完整的硬件验证。

#### TCA2 架构

- 数据和指令都是围绕 **3 trits** 组织。
- 物理三电平采用 `-5 V / 0 V / +5 V`。
- 指令存储器和寄存器存储器分离，属于简化的 Harvard 风格。
- 时钟分为 `FETCH` 和 `EXECUTE` 两相。
- 指令集非常小：

| 编码族 | 指令 | 作用 |
|---|---|---|
| `0xx` | LWI | 将立即数装入 A |
| `Txy` | CMP | 比较操作数并设置状态 |
| `1xy` | BE | 根据状态进行分支 |

这里的 `T` 表示负 trit。原报告的编码实质是 `-1xy=CMP`、`0xx=LWI`、`+1xy=BE`。

#### 硬件结果

报告给出了反相器、三值多路器、存储单元、全加器、符号检测和胶合逻辑等电路。附录显示：

- 存储板使用 4 个主从 D 型三值触发单元。
- 多路器、存储、全加器、符号检测等板卡均有制作或测试记录。
- TCA2 的完整猜数程序在晶体管级仿真中跑通。
- 实物 TCA0 没有形成一台完整可运行的 TCA2 CPU。
- ROM 板因开关引脚接反未正常工作，多路器板只部分工作。

因此，最准确的表述是：**项目完成了完整 3-trit CPU 的晶体管级仿真闭环，也制作了若干基础板卡，但没有完成一台被充分验证的完整实体 CPU。**

#### 对当前项目的价值

这是资料中对当前任务最直接的一份：

- 它证明 3-trit 宽度足以做一个可编程教学机。
- 它提供“先基础门和寄存器，再最小指令集，再跑应用”的合理次序。
- 它展示了 ROM、MUX、寄存器和时序电路的失败模式，能帮助提前设计板级测试点。

但不建议照搬：

- `±5 V` 电平和 2008 年的分立 MOS/电阻网络未必适合现有器件。
- 指令集过度针对猜数程序，不适合作为长期 ISA。
- 报告中的 3-trit CPU 与 Setun-70 的 6-trit tryte、18-trit栈操作数并不兼容。

### 3.2 Efficient Ternary Logic Circuits

文件：`TEmerging_24.pdf`

#### 资料定位

这是 2024 年 IEEE Transactions on Emerging Topics in Computing 论文。它研究的是：

- 非平衡三进制 `0/1/2`
- 平衡三进制 `T/0/1`
- 三值循环增量/减量门
- 半加器、全加器
- 6×6-trit Wallace 树乘法器

它是当前资料中最接近“现代三值 ALU 组合逻辑”的论文。

#### 加法器核心思想

论文将三值和拆成循环变换：

- `TIC(x) = x + 1 mod 3`
- `TDC(x) = x - 1 mod 3`

根据另一个输入选择原值、TIC 或 TDC，可以生成和位。平衡三值加法中：

- `+1 + +1` 产生本位 `-1` 和进位 `+1`
- `-1 + -1` 产生本位 `+1` 和进位 `-1`
- 进位本身也是 `{-1,0,+1}` 三值量

这意味着平衡三值 ALU 的进位不能直接套用二进制 `carry/borrow` 标志。

#### 论文关键结果

| 电路 | 论文报告结果 | 条件/边界 |
|---|---|---|
| 非平衡全加器 | 0.5 GHz 下 57 ps、11 aJ PDP | 32 nm CNTFET SPICE 模型 |
| 平衡全加器 | 0.5 GHz 下 46 aJ PDP | 与同平台既有设计比较 |
| 非平衡 6×6 Wallace | 647 ps、23.77 fJ | 未包含完整物理互连验证 |
| 平衡 6×6 Wallace | 1300.6 ps、18.299 fJ | 同上 |
| CMOS180 STI | 357 ps、40.7 aJ | 180 nm PDK，版图后仿真 |
| CMOS180 非平衡半加器 | 1.199 ns、1.182 fJ | 180 nm PDK，版图后仿真 |

论文报告相对同文对照设计的平均 PDP 改善：

- 非平衡全加器：16.1%
- 平衡全加器：22.8%
- 平衡 Wallace 乘法器：17.5%
- 非平衡 Wallace 乘法器：36.8%

#### 应谨慎理解的地方

- 主要加法器和乘法器结果来自 CNTFET 模型，不是流片芯片实测。
- 180 nm CMOS 只验证了 STI 和非平衡半加器，没有验证完整 3-trit ALU。
- 缺少完整的 PVT、Monte Carlo、噪声裕量、级联扇出和系统互连评估。
- 论文所称的逻辑综合是器件网络映射，不等同于普通 Verilog/Liberty 自动综合。
- 单个三值门与单个二值门并非等容量比较。3 trits 有 27 个状态，公平基线更接近 5 bits，而不是 3 bits。
- 论文也承认没有直接完成二值与三值完整加法器的公平比较。

#### 对当前项目的建议

可直接复用的是**功能结构**：

1. TIC/TDC
2. 平衡三值半加器
3. 平衡三值全加器
4. 3-trit ripple-carry adder

暂不应优先实现 Wallace 乘法器。对 3×3-trit 这种很小的宽度，压缩树的布线开销可能抵消收益；应在基本 ALU 跑通后，再同时综合阵列乘法器和 Wallace 版本进行选择。

### 3.3 FeRAM 三值权重与存内计算

文件：`post-print-a-ternary-weight-mapping-and-charge-mode-readout-scheme-for-energy-efficient.pdf`

#### 资料定位

这是 2023 年 IEEE AICAS 会议论文后印本，研究 FeRAM 交叉阵列中的神经网络向量-矩阵乘法，不是 Setun、CPU 或离散三值 ALU。

#### 三值编码方法

物理单元本身仍是二态 `C_ON/C_OFF`。一个平衡三值权重用两个 FeRAM 单元组成差分对：

| 正端 | 负端 | 权重 |
|---|---|---|
| ON | OFF | `+1` |
| OFF | ON | `-1` |
| OFF | OFF | `0` |

因此：

- 1 trit 需要 2 个二态 FeRAM 单元。
- 2-trit 权重需要 4 个单元并形成 9 个量化级。
- `ON/ON` 状态没有用于编码。

阵列通过两个相位工作：先充电，再将电荷转移到参考电容，实现模拟点积。论文使用 `64×64` 阵列模型。

#### 实验结果与边界

- 使用 ResNet-32，约 0.45M 参数。
- Google Speech Commands 35 类任务。
- 2 trits/9 级权重。
- 在 5% 器件变异仿真下报告 97.12% 准确率。

这些结果来自 Python 和器件模型仿真，不是完整芯片实测。论文没有给出：

- pJ/MAC
- 真实阵列面积
- 充电/转移绝对延迟
- ADC/DAC、参考电容和外围电路开销
- 完整模型如何分块到大量 `64×64` 阵列

#### 与三值 CPU 的关系

可以借鉴：

- `-1/0/+1` 的统一编码表
- 差分正/负通道
- 器件偏差、噪声和变异测试方法

不能误用：

- 97.12% 分类准确率不能证明 CPU 或 ALU 正确。
- 2-trit/9-level 不能解释为实现了通用 2-trit 寄存器。
- 模拟电荷求和没有 CPU 所需的精确进位、溢出、寻址和控制流。

这篇论文更适合作为未来“三值 CPU + 专用矩阵协处理器”的远期参考。

### 4.2 必须区分 Setun 与 Setun-70

两代机器不是同一个架构。

#### 原 Setun

可检索资料给出的核心特征是：

- 单地址、顺序执行机器
- 9-trit 指令字
- 18-trit 主算术寄存器 `S/R`
- 5-trit 索引/计数类寄存器
- 操作存储器为 162 个 9-trit 单元，常描述为 3 页×54 单元
- 外部磁鼓按页扩展

#### Setun-70

2011 年 Brusentsov 与 Ramil Alvarez 的英文论文给出的关键事实是：

- 程序最小可寻址单位为 **6-trit tryte**
- 算术采用 **18-trit 操作数栈**
- 程序使用 POLIZ，即逆波兰/后缀形式
- 寻址字长度可为 1～3 个 tryte，并将操作数送入栈
- 操作存储器为 **9 页×81 trytes**
- 同时只通过 3 个指示/页寄存器打开 3 页
- 具有操作数栈和返回地址栈，形成双栈结构
- 操作 tryte 分为 27 个基本、27 个辅助和 27 个用户可编程操作

Setun-70 的特色不是“使用三进制的普通寄存器机”，而是：

> 平衡三进制 + 6-trit 字节式指令单元 + 18-trit 栈操作数 + 分页窗口 + 双栈结构化程序。

这也是为什么它更像一种栈式字节码机器，而不像带一组通用寄存器的 RISC-V。

#### 关于“单子函数”和阈值逻辑

一个三值单输入、单输出函数，需要为 3 个输入值各指定一个输出值，因此共有：

`3^3 = 27`

阈值实现形如：

1. 输入 `i` 乘常数 `k`
2. 与上下阈值 `t+`、`t-` 比较
3. 大于上阈值输出 `+1`
4. 小于下阈值输出 `-1`
5. 中间输出 `0`

Merrill 表中的每一列就是一个单子函数，三行 `k/t+/t-` 是实现它的一组参数。只有 17 个函数能用这种“线性缩放 + 两个阈值”直接实现；其余函数需要组合更多逻辑。

这对硬件的意义是：不要把 27 个函数都做成独立门。第一版只选择真正服务于算术和控制的函数，如 STI、PTI、NTI、TIC、TDC 和符号/零检测。

## 6. 跨资料得到的架构认识

### 6.1 三进制编码必须先冻结

资料同时出现：

- 平衡三进制 `{-1,0,+1}`
- 非平衡三进制 `{0,1,2}`
- 不同文本符号：`T`、`-`、`/` 表示负 trit
- 不同物理电平：`-V/0/+V` 或 `0/VDD/2/VDD`

当前项目建议固定：

| 逻辑值 | 文本 | RTL 编码示例 | 物理电平 |
|---:|---|---|---|
| -1 | `T` | `2'b10` | 由现有器件方案决定 |
| 0 | `0` | `2'b00` | 同上 |
| +1 | `1` | `2'b01` | 同上 |
| 非法 | 不显示 | `2'b11` | 仿真中断言 |

物理器件若已有不同编码，应保留器件定义，但软件、RTL、波形和文档必须通过唯一转换层统一。

### 6.2 数据宽度与指令宽度可以不同

历史 Setun-70：

- 指令最小单位：6 trits
- 栈操作数：18 trits

当前第一版：

- 数据寄存器：3 trits，范围 `-13..+13`
- 指令：建议 6 trits，便于容纳操作码和小立即数
- 加法结果：3 trits + 一个三值进位，或保留 4-trit 内部结果
- 乘法结果：若以后实现，3×3-trit 应保留 6 trits

因此，“寄存器是 3 trits”并不要求“每条指令也是 3 trits”。

### 6.3 第一版不需要通用寄存器堆

资料给出两种可行风格：

- TCA2：少量显式寄存器，适合看懂数据流
- Setun-70：操作数栈 + 返回栈，适合小指令和 POLIZ

为了快速跑通，建议先用：

- `T`：栈顶 3-trit 寄存器
- `S`：次栈顶 3-trit 寄存器
- `PC`：程序计数器
- `IR`：6-trit 指令寄存器
- `FLAGS`：负/零/正或溢出状态
- 一个很小的栈 RAM，深度先定 9 或 27

这比立即实现 RISC-V 风格通用寄存器堆更符合 Setun-70 的思想，也比无限深软件列表更接近硬件。

## 7. 当前 Python 模拟器与历史资料的差异

当前仓库中的 `setun70.py` 是教学模拟器。它采用了 Setun-70 的名称和若干思想，但不能当作精确历史复刻。

| 项目 | 历史资料中的 Setun-70 | 当前 Python 模拟器 |
|---|---|---|
| 指令单元 | 6-trit tryte | 6-trit `Syllable` |
| 算术操作数 | 18 trits | Python 任意精度整数 |
| 操作数栈 | 有限硬件栈/存储结构 | Python `list`，未限制深度 |
| 返回栈 | 独立系统栈 | Python `list`，未限制深度 |
| 操作存储器 | 9 页×81 trytes | 27 页×81 单元 |
| 可见页 | 3 个页寄存器选择 | 3 个字典映射，初值固定 |
| 指令体系 | 27+27+27 操作分类 | 项目自定义的简化操作码 |
| 地址 | 1～3 tryte 寻址字、分页窗口 | 部分控制流用 `page*100+offset` 十进制打包 |
| 精确性目标 | 实际历史机器 | 教学演示和简单编程 |

最明显的冲突是内存页数：

- 2011 年历史论文明确写 **9 pages × 81 trytes**
- 当前代码和说明写 **27 pages × 81 syllables**

在找到更原始且可核对的 Setun-70 技术手册前，应把它记录为“重建实现与历史摘要不一致”，不能悄悄选择其中一个当作定论。

当前模拟器可继续用于：

- 解释 POLIZ
- 展示 T/S 栈顶
- 演示 PC、IR、ALU、FSM 和内存
- 快速编写例程

但硬件设计前需要另写一份**本项目自己的可执行 ISA 规范**，明确位宽、溢出、栈深、地址和周期行为。

## 8. 面向 3-trit 硬件的实施路线

### 阶段 0：冻结接口合同

必须先写清：

- trit 的逻辑/RTL/物理编码
- 3-trit 数值范围 `-13..+13`
- 加法溢出采用回绕、饱和还是额外进位
- 比较结果和 FLAGS 的定义
- 非法编码如何处理
- 组合门负载、输入斜率和测试电压

交付物：`ternary_encoding.md`、完整真值表、参考转换函数。

### 阶段 1：1-trit 组合基础模块

优先级：

1. STI/取负
2. 正、负阈值检测
3. TIC/TDC
4. MUX
5. 平衡三值半加器
6. 平衡三值全加器

验证要求：

- 全部输入组合穷举
- 电平和逻辑语义同时检查
- 加负载后的传播延迟
- PVT/器件偏差
- 级联后的噪声裕量

### 阶段 2：1-trit 时序单元与 3-trit 寄存器

参考优先级：

1. Mouftah 三值存储/时序论文
2. Shou 的 CMOS ternary latch
3. Kameyama 的无静态冒险 T-gate
4. TrinaryWiki 中锁存器、tri-flop 和寄存器工程
5. CPE 报告的存储板

先完成 1-trit D latch/flip-flop，再复制成 3-trit 寄存器。必须验证：

- 建立/保持时间
- 时钟边沿附近的中间电平
- 上电/复位状态
- 连续多周期保持
- 三个 trit 同时翻转
- 9 种单 trit 状态转移，包括直接 `-1 ↔ +1`
- MUX 或总线接入后的输出反灌与隔离

### 阶段 3：3-trit ALU

第一版只做：

- `PASS`
- `NEG`
- `ADD`
- `SUB`
- `CMP`

实现顺序：

1. 3 个平衡三值全加器构成 ripple adder
2. NEG 作为逐 trit 取反
3. SUB 复用 `A + NEG(B)`
4. CMP 产生负/零/正
5. 明确最高位进位和数值溢出的区别

暂不做乘法、除法、复杂布尔函数和 Wallace 树。

### 阶段 4：最小可编程 CPU

建议的数据通路：

- 3-trit `T`、`S`
- 6-trit `IR`
- `PC`
- 深度 9 或 27 的操作数栈
- 小型程序 ROM
- 单端口数据 RAM
- FETCH/DECODE/EXECUTE 多周期 FSM

最小指令建议：

| 指令 | 栈效果 | 用途 |
|---|---|---|
| `LIT n` | `( -- n )` | 小立即数 |
| `ADD` | `( a b -- a+b )` | 加法 |
| `NEG` | `( a -- -a )` | 取负 |
| `CMP` | `( a b -- )` | 设置负/零/正状态 |
| `JMP a` | `( -- )` | 无条件跳转 |
| `JZ a` | `( -- )` | 条件跳转 |
| `OUT` | `( a -- a )` | 演示输出 |
| `HALT` | `( -- )` | 停机 |

跑通标准：

1. `3 + 4 = 7`
2. `5 + (-2) = 3`
3. 从 3 倒数到 0
4. 比较两个输入并输出较大者

完成这些后，再决定是否扩为历史方向的 18-trit 栈机。

- 能直接作为 RTL 对照的官方测试程序和结果

- TrinaryWiki 工程的依赖模型、版本和可复现运行说明

因此，当前最稳妥的研究表述是：

> 我们先设计一台受平衡三进制和 Setun-70 栈式思想启发的 3-trit 教学 CPU；待原始资料核实后，再决定是否向历史兼容的 6-trit/18-trit Setun-70 重建扩展。

## 11. 最终建议

这批资料已经足够支持“先做 3-trit 基础模块，再跑通最小 CPU”的路线。最值得立即执行的组合是：

- 用 `TEmerging_24` 的平衡三值加法结构定义组合算术；
- 用 Mouftah/Shou/Kameyama 和 Wiki 工程选择时序单元；
- 用 CPE 项目的验证次序组织板级和仿真测试；
- 用 Setun-70 的双栈/POLIZ 思想设计最小编程模型；
- 明确将当前 Python 模拟器标为教学参考模型，而不是历史黄金模型。

第一阶段成功的标志不应是“实现了很多三值函数”，而应是：

> 一个有明确编码、有穷举测试的 3-trit 寄存器和 ALU，在有限栈、ROM、PC 与 FSM 上稳定执行一个带循环和条件分支的小程序。
